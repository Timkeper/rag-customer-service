# AI 产品经理术语白话表（Day 1 核心产出）

> 面试用得上的"人话版"解释。面试官问"你理解RAG吗"，照着这个答就行。

---

## 一、大模型基础（必会）

### 1. LLM（大语言模型）
- **白话**：一个读了全网内容的"超级鹦鹉"，你给它开头，它接下去。
- **例子**：DeepSeek、ChatGPT、通义千问、文心一言。
- **PM要懂**：它是"概率预测"，不是"查数据库"，所以会胡说（幻觉）。

### 2. Token（词元）
- **白话**：大模型计费的"字数单位"。1个汉字≈1.5-2个token。
- **例子**："我爱AI"≈ 4-5个token。
- **PM要懂**：影响成本和速度，输入+输出都算token。

### 3. 上下文窗口（Context Window）
- **白话**：大模型一次能"记住"多少内容。像人的短期记忆。
- **例子**：DeepSeek 64K、Claude 200K、GPT-4 128K。
- **PM要懂**：决定能塞多少资料/对话历史，超了就"忘"前面的。

### 4. 幻觉（Hallucination）
- **白话**：AI一本正经地胡说八道。
- **例子**：问"退货政策"，它编一个不存在的"30天退款"。
- **PM要懂**：这是客服场景最大的坑，RAG就是用来治幻觉的。

### 5. 温度（Temperature）
- **白话**：AI有多"放飞"。0=死板确定，1=天马行空。
- **PM要懂**：客服场景温度设低（0.3左右），要准确；创意场景设高。

### 6. Top-p
- **白话**：AI选词的"范围"。和温度类似，控制随机性。
- **PM要懂**：一般和温度二选一调，客服场景建议 top-p=0.9。

## 二、三种能力增强方式（面试必问）

### 7. Prompt Engineering（提示工程）
- **白话**：教AI怎么干活的话术。
- **例子**："你是电商客服，回答退货问题时，先说政策，再说流程"。
- **PM要懂**：最便宜的能力增强，改字就行，但要反复测。
- **类比**：给员工写SOP。

### 8. RAG（检索增强生成）
- **白话**：先查资料再回答。"开卷考试"。
- **流程**：用户问 → 去知识库找相关内容 → 把内容塞给大模型 → 大模型基于资料回答。
- **PM要懂**：治幻觉的利器。你的客服项目核心就是RAG。
- **类比**：让客服翻手册再答客户。

### 9. 微调（Fine-tuning）
- **白话**：给AI重新"培训"，改变它的风格/能力。
- **例子**：用1万条客服话术训练，让AI说话更像金牌客服。
- **PM要懂**：成本高、周期长，一般用RAG或Prompt解决不了的才微调。
- **类比**：送员工去培训3个月。

### 10. 三者怎么选？（面试高频）
| 场景 | 用什么 |
|---|---|
| 让AI按固定格式回答 | Prompt |
| 让AI基于公司知识答（治幻觉） | RAG |
| 让AI改变说话风格/专业领域 | 微调 |
| **默认顺序**：先Prompt → 不行加RAG → 还不行才微调 |

## 三、Agent 相关（你的项目加分项）

### 11. Agent（智能体）
- **白话**：会"动手"的AI。不只回答，还能调工具办事。
- **例子**：用户说"退A123" → Agent调退款API → 真退了。
- **PM要懂**：RAG是"会说"，Agent是"会做"。你的项目是RAG+Agent。
- **类比**：客服从"顾问"升级成"业务员"。

### 12. Function Calling（函数调用/工具调用）
- **白话**：Agent调用外部工具的"接口机制"。
- **例子**：AI判断要查订单 → 输出 {tool: query_order, order_id: A123} → 系统执行 → 返回结果给AI → AI回答用户。
- **PM要懂**：你的5个工具就是5个Function。设计工具的description是PM的活。

### 13. ReAct（推理+行动）
- **白话**：AI先"想"再"做"的循环。Thought → Action → Observation。
- **PM要懂**：Agent的决策模式，Dify的Agent模式默认用类似机制。

## 四、RAG 技术细节（作品集要写得出来）

### 14. Embedding（向量化）
- **白话**：把文字变成一串数字（向量），让机器能算"相似度"。
- **例子**："退货"和"退款"向量很近，"退货"和"天气"很远。

### 15. 向量数据库
- **白话**：专门存向量、能快速找"最相似"的数据库。
- **例子**：Milvus、Pinecone、Dify内置的。
- **PM要懂**：知识库就是存在这里的。

### 16. Chunking（分块）
- **白话**：把长文档切成小块，方便检索。
- **PM要懂**：切太大召回不准，切太小丢失上下文。一般300-500字一块。
- **你的项目**：FAQ按"Q&A对"切，每对一块。

### 17. 召回（Retrieval）
- **白话**：从知识库里找出"最相关"的几块。
- **PM要懂**：Top-K=找最相关的前K块，一般K=3-5。

### 18. Rerank（重排序）
- **白话**：召回后再精排一次，提高相关性。
- **PM要懂**：召回快但粗，Rerank准但慢，两者结合效果好。

## 五、评测相关（你的杀手锏，Day 3-4 深入）

### 19. 准确率（Accuracy）
- **白话**：答对了多少。最核心指标。

### 20. 召回率（Recall）
- **白话**：该找的信息找全了没。
- **注意**：RAG里有"检索召回率"（知识找全没），客服里有"业务召回率"（该转人工转了没）。

### 21. LLM-as-a-Judge（用大模型当评委）
- **白话**：让另一个大模型给回答打分。省人工。
- **PM要懂**：适合大批量初筛，但终评还是要人。

### 22. HHH 原则
- **白话**：AI要 Helpful（有用）、Honest（诚实）、Harmless（无害）。
- **PM要懂**：评测时的三大价值维度。

## 六、面试金句（背下来直接用）

1. "大模型本质是概率预测，所以会幻觉，RAG的本质是给它'开卷考试'降低幻觉。"
2. "Prompt、RAG、微调是能力增强的三层，成本递增，我优先用低成本的方案。"
3. "好的AI产品不是全程自动，而是知道自己的边界——该转人工就转人工。"
4. "评测的价值不是打分，而是定位可优化点，形成'评测-分析-优化'闭环。"
