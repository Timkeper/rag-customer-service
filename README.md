# 智答 ZhiDa —— 能办事的电商售后 Agent

> 不做挡量的问答机器人，做**额度内直接把事办完、全程可审计、还能反向输出经营洞察**的售后 Agent。
> 对标海外 Agentic Resolution 趋势（Intercom Fin 3 / Sierra / Decagon 的"端到端解决工单"）——国内 AI 客服普遍停留在"问答 + 转人工"。

## v1 → v2：从作品集 Demo 到可部署产品

| 能力 | v1（作品集版） | v2（当前版本） |
|------|--------------|--------------|
| 对话 | 单轮无记忆 | **多轮会话 + 指代改写**（"那退款呢"能正确检索） |
| 身份 | 输订单号可查/退任何单 | **手机尾号+订单号自助验证**，会话绑定用户，越权操作一律拒绝并审计 |
| 办事 | 只提交申请单 | **Agentic 办结**：额度内自动退款/补发/改地址，含策略引擎、审计日志、24h 可撤销回执 |
| 转人工 | 一句话术（存根） | **工单落库 + AI 对话摘要 + 坐席工作台**（接管/回复/解决，买家侧无缝切换） |
| 评测 | 工具准确率 + 延迟，质量分 0/50 未打 | **LLM-as-Judge 自动质量评分**，50 题 × 三方案全指标真实数据 |
| 部署 | 本地 Gradio 演示 | **FastAPI + SSE 流式 + Web 三端**（买家/坐席/洞察），Docker 化可上云 |

## 三个页面

| 入口 | 用户 | 能力 |
|------|------|------|
| `/` | 买家 | 验证订单 → 多轮咨询 → 额度内直接办理（回执可撤销）→ 转人工 |
| `/console.html` | 客服坐席 | 登录 → 工单列表（含 AI 摘要）→ 查看完整对话 → 接管/回复/解决 |

## 信任设计（本项目的产品核心）

**AI 能办多少事 = 策略引擎给它多少权限，且每一步可审计、可撤销。**

| 动作 | 边界条件 | 超界处理 |
|------|---------|---------|
| 自动退款 | 单笔 ≤ ¥500，当日累计 ≤ ¥1000，当日 ≤ 3 次 | 拒绝 + 审计 + 转人工 |
| 自动补发 | 单笔 ≤ ¥300，当日累计 ≤ ¥600，当日 ≤ 2 次 | 拒绝 + 审计 + 转人工 |
| 改地址 | 仅"待发货"订单 | 拒绝 + 审计 + 转人工 |
| 越权（操作他人订单） | 一律拒绝 | 审计 + 转人工（评测指标：越权动作数 = 0） |
| 办结确认门 | 用户问"能退吗"≠"确认办理"，问句不允许触发办结 | 返回"需先向用户确认" |

每笔办结动作（**包括被拒绝的**）写入 `audit_log`：时间/用户/订单/动作/金额/决策/命中的策略/AI 的理由。用户收到结构化回执，24 小时内可一键撤销（状态自动回滚）。

## 评测体系（真实数据，可复现）

- **评测集**：8 类场景 50 题，含类别/期望工具/期望参数/答案要点
- **三方案对照**：裸模型 / 纯 RAG / Agent
- **自动指标**：工具选择准确率、延迟、转人工触发、误调用
- **v2 新增 LLM-as-Judge**：按评分标准自动打 准确性/相关性/完整性/安全性（1-5）+ 任务完成 + 参数正确（温度=0，失败留空不造假）
- **回归机制**：Bad Case 修复后重跑评测集验证

```bash
cd src && python run_eval_v2.py all      # 约30分钟，产出 CSV + 图表
```

## 非目标与已知边界（诚实声明）

- 单租户演示模式（无多商家 SaaS 注册体系）
- 无高可用设计（限流/重试/降级未做，对话以锁串行化）
- 未接入微信/电商平台生态
- RAG 未做 rerank 调优（改写仅用于多轮指代消解）

## Roadmap

- **主动式售后**：物流异常主动触达 + 补偿方案——从"你问我答"到"我先开口"
- 坐席 Copilot：摘要之外提供推荐回复与情绪标注
- rerank + 召回评测（Recall@K / MRR）
- 评测扩充：自动办结率、办结 vs 转人工处理时长
